- 项目地址与 Git origin 为 https://github.com/RockBase-lab/NM-SmallTV-Pro.git 。GitHub 更新资产名称与 CI 同步；未推送代码或发布 GitHub Release。

## 崩溃证据与边界

读回旧版 3.13.0 的重启原因为 Exception/panic。ESP32 旧版没有保留异常栈，也没有 core dump 分区，当时串口未连接，无法追溯具体指令。用户确认之前没有操作。COM3 捕获下重启恢复运行，382 秒内进行了 25 次只读股票搜索，没有复现 panic。这不能证明空闲时的后台崩溃已修复。

3.13.1 通过 Arduino 已有的 panic 回调保留原因、PC、最多 12 个回溯地址、最后执行阶段、近似 uptime 和版本到带校验的 RTC 记录。回调不分配内存，不打印日志，不替换 IDF 的原有异常流程。abort/assert 保存原始详情；历史记录不充当之后未捕获 watchdog 的当前故障地址。完整断电会丢失 RTC 内容。原始 panic 根因仍未确认，需结合下一次记录、对应 ELF 与串口输出分析。

## 构建与验证

- 普通版与 WireGuard 版 PlatformIO 构建均通过。
- OTA 槽 1,966,080 字节，普通版 1,912,288 字节（余 53,792），WireGuard 版 1,957,776 字节（余 8,304）。两者通过至少 8,192 字节余量门限；后者接近容量上限。
- 最终 WG ELF：panic 回调位于 IRAM，阶段与版本数据位于 DRAM，168 字节记录位于 RTC；所调用的 memset 位于 ROM。
- 天气原生渲染与地点策略测试通过；日出日落测试 2,246,751 + 67 次检查，零失败。
- 字体 105 个样本与 spaceman 14 帧分别比较原图及 C++ 解码输出，无像素差异；压缩资源总计减少 1,242 字节。图片库仍为全彩 v2 JPEG。
- 22 个 Node 网页回归文件全部通过；崩溃记录校验、历史/当前记录区分、TCPIP DNS 上下文与两项诊断连接检查通过。状态 JSON 的 6 个样本逐字节一致，64 位原生内存检查显示流式输出零堆分配；当前 WSL 缺少 32 位开发头文件，未完成 32 位内存检查。
- 模式设置 81 项检查、应用调度/取消请求及真实导入回滚检查通过。WSL 未提供 Node，因此网页测试在 Windows 运行。
- 中英文 PDF 各 17 页、14 章，已渲染检查；Astro 文档站点 23 页构建通过。网页压缩头与当前 HTML/搜索模块一致。

- 已通过网页 OTA 更新 192.168.124.14 的 WireGuard 版，固件 SHA-256 为 `80d15e520f69883e99908336eeb35711aa93f7737b8b4a32710092b67d593341`。
- 读回标识 `nm-smalltv-pro`、版本 3.13.1、变体 esp32-wg、新 GitHub 地址；网页内容与发布包逐字节一致。
- OTA 前后配置逐项相同，随后只按用户要求将 clock 的五个地点/时区字段设为成都。其他设置和独立雷达中心不变。正常重启后再次逐项核对配置，全部保持。

- 新版 AAPL 与 ON 在线股票检索均返回 HTTP 200。OTA 后首次运行至 uptime 508 秒，未出现异常重启；COM3 观察段未见 assert、Guru Meditation 或 Backtrace。之后正常重启，再观察至 uptime 74 秒，启动完成且未进入安全模式。COM3 已释放。

发布包附 `device-verification.json` 与两段串口日志，并重新生成 SHA256SUMS。实机没有故意触发 panic，RTC 捕获路径依靠原生回归、框架接口审查及最终 ELF 检查验证；当前短时运行通过不能代替长时间稳定性验证。原始空闲 panic 的根因仍待下一次有效异常记录确认。
