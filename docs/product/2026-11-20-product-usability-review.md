# SmallTV 产品使用逻辑复盘

日期：2026-11-20。范围：当前工作区全部产品能力，以 NM-TV-154 为主要使用路径；固件基于 3.12.0，包含本地功能及易用性更新。本报告区分源码／自动化验证、设备运行验证与用户实际观察。

## 1. 产品定位与使用路径

产品是一台通过局域网页面配置的桌面信息屏。屏幕负责展示；顶部单触摸区负责快捷切换，不承担多级菜单操作。网页是主要控制入口。首次使用的目标应是先看到正确的本地时间和一个可用页面，再逐步接入其他数据。

推荐旅程：供电 → 加入 2.4 GHz WiFi → 打开设备地址 → 选择城市并核对时区 → 在 General 选择一个应用并保存 → 验证该应用 → 添加 Carousel／Timer → 可选集成 → 导出备份。升级路径单独区分应用 OTA、资源库更新和 factory 安装，避免把三种操作混为一谈。

NM-TV-154 出厂使用 Detailed weather；未配置地点时明确提示设置，不替用户猜城市。已有保存模式在重启、升级后继续保留。当前生产镜像预设网络不可达时进入配网热点，热点默认密码为 12345678；手册同时解释其他板型可能使用开放热点。

## 2. 统一的操作模型

| 层次 | 含义 | 用户操作 |
| --- | --- | --- |
| 显示应用 | 股票、天气、图片、雷达等 | General 选择单应用后保存 |
| 应用调度 | Carousel 或每日 Timer | 选择参与应用／时间表并保存 |
| 应用内部内容 | 股票代码、图片、天气布局 | 各应用独立的轮换开关与间隔 |
| 临时覆盖 | 通知、网络信息、屏幕刷新、手动预览 | 到期或对应动作后恢复正常显示 |
| 编辑状态 | 网页表单中尚未保存的改动 | 全局 Save settings 保存；切标签不保存 |
| 资源文件 | 图片包与主题包 | 安装／删除即时变更文件，独立于设置备份 |

Carousel 按勾选应用的固定顺序轮播，网页间隔单位为分钟；0.5 表示 30 秒。Timer 的四条记录按设备本地时间每日执行，跨午夜延续上一条，依赖已同步的时钟。短触摸默认 Next page，长触摸约 600 ms 默认 Home；Timer 的手动预览持续 15 秒。图片下一张由相册内部轮换控制，Next page 切换的是应用。

## 3. 已修正的问题

| 问题与影响 | 本轮处理 | 证据位置 |
| --- | --- | --- |
| 未设天气位置时自动查询首尔，用户会误认为是自己的天气 | 未设／无效坐标停止请求，天气页面显示设置指引；纯大时钟仍可使用 | src/features/weather/WeatherLocation.h、WeatherClient.cpp、WeatherMode.cpp；tests/weather/test_location.py |
| Weather 与 Display 的共享位置不同步，保存可能覆盖刚选城市 | 城市选择、手动输入双向同步，手动改坐标清理旧地点名称 | src/webui.html；tests/weather/test_webui.js |
| 合法零纬度／零经度被默认值覆盖 | 使用显式空值判断，单个零坐标保留，0/0 约定为未设 | 同上及 WeatherLocation.h |
| 选城市后仍可能保留不相符时区 | 对已支持的城市时区自动选择，并要求用户核对 | src/webui.html；tests/weather/test_webui.js |
| 默认 Carousel 包含空列表和未接入服务 | 新配置默认仅选择 Stock 1 与 Weather；保留已有明确选择 | src/Settings.cpp；tests/mode/test_settings.cpp |
| Status 的 Mode=STA/AP 容易被误认为显示应用 | 改为 Network mode／网络模式 | src/webui.html；中英文词条 |
| 图片提示硬编码触摸行为，天气提示错误声称要重启 | 图片提示遵循可配置触摸动作；天气明确保存后生效 | src/webui.html |
| 快捷选择天气布局后仍可能被自动轮换覆盖 | 布局快捷操作同时关闭天气布局自动轮换 | src/webui.html；tests/weather/test_clocks.js |
| 导入旧备份时空密码无法清掉后加的密码或密钥 | 验证备份基本字段；事务中恢复默认再加载完整备份，保存失败回滚 | src/WebPortal.cpp；tests/mode/test_import.py |
| 无有效 Timer 时退出网络信息页可能不恢复提示 | 到期同时清除当前页面和提示绘制状态，由主显示流程恢复 | src/main.cpp；tests/mode/test_dispatch.py |
| README 与旧指南存在每次开机强制天气、Display→Mode 等冲突 | 完整中英手册成为主入口；五份旧指南改为一致的概览；修正 Usage／Radar 操作入口 | README.md、docs/astro.config.mjs、docs/src/content/docs/manual/、getting-started/setup.md |

以上为局部修正，保留现有标签结构和明确保存的用户配置，未重新设计固件架构或改变分区。

## 4. 能力与前置条件

| 能力 | 最小可用条件 | 需要明确的边界 |
| --- | --- | --- |
| Weather | 位置、时区、互联网／NTP | Open-Meteo 免费服务有非商业使用条件；城市搜索与设备天气请求来自不同端 |
| Stock 1／2、Crypto | 正确代码和来源、网络 | 默认三星／NVIDIA／Apple；Stock 2 初始空；公开行情存在延迟、限流或区域限制 |
| Pictures | 有效本地 .stheme 包 | 全彩 v2 图片包需单独更新；直接 JPG／PNG／GIF 上传尚未支持 |
| Theme clocks | 已选主题包、时区／NTP | 与四个内置天气布局不同；与图片共享空间及包数量限制 |
| Radar | 观测中心、有效飞机源 | 不把无流量、过滤为空和请求错误混为一谈；未实现独立雷达项目完整航班详情浏览 |
| Usage | 电脑 daemon 持续运行 | 设备不会自行查询账户用量 |
| Home Assistant | MQTT broker 和兼容屏幕 JSON | 仅填 broker 不会自动产生面板；首次启用／关闭需要重启 |
| WireGuard | 支持构建、有效配置和时间 | 仅一个 IPv4 Allowed IPs CIDR，非桌面完整配置导入器 |

中文网页与设备字体是不同能力。NM-TV-154 使用 ASCII 字体，地点／通知建议简短英文。8 MB Pro 当前构建与 NM-TV-154 的功能开关不同，手册给出矩阵，不能凭外壳或容量推断功能。

## 6. 验证结果

本轮 20 项 Node 网页回归全部通过。Native 设置 81 项检查通过，执行实际模式调度、网络信息超时分支和备份导入 handler 的回归通过，覆盖鉴权、非法输入、完整空秘密字段恢复、保存失败回滚。天气单位、Open-Meteo 解析、渲染边界、启动策略、位置判断和时钟需求检查通过；宇航员资源测试通过。额外运行密码设置 56 项、太阳位置及调光 2,246,818 项和 DNS／NTP 回调上下文回归，全部通过。

## 7. 后续产品改进建议

本轮以保持现有习惯、修复不自洽行为为目标。后续适合单独设计和验证：首次设置向导；可选服务的连接测试按钮；明确的未保存提示；网页照片转包与裁剪；Timer 空表和重复时间的更强校验；跨硬件自动匹配升级包。上述建议没有作为已经实现的功能写入手册。

实际面板颜色、触摸手感和长时间稳定性仍需结合实物观察。公开数据服务可用性不由本地回归保证；一次串口观察也不能替代长期运行验证。
