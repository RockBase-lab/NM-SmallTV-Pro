| 项目 | 内容 |
| --- | --- |
| 调研日期 | 2026-11-19 |
| 参考设备 | SmallTV-Ultra |
| 参考固件 | Ultra-V9.0.54 |
| 参考入口 | `http://192.168.124.31/`（自动跳转 `/settings.html`） |
| 目标项目 | SmallTV Pro / NM-TV-154 Modded Firmware v3.12.0 |

## 1. 一页结论

### 1.1 产品判断

参考设备的优势不是底层能力更强，而是把常用能力做成了**直接、低学习成本的设置项**：主题一键切换、主题自动轮播、时间颜色和格式、Wi-Fi 延迟连接、天气单位、相册及 GIF 文件管理。

当前项目已经拥有更完整的网络、显示、主题和系统能力，不应推倒重做。建议保留现有单页标签式 Web UI、统一保存、主题包、配置备份、密码保护和多网络机制，只补齐参考设备中仍有用户价值的体验。

### 1.2 建议首发范围

按“用户价值、实现成本、NM-TV-154 资源风险”综合排序，建议首发包含：

1. **Wi-Fi 扫描结果信号分级**：在现有 dBm 旁增加强／中／弱，保留 dBm，避免只给伪精确百分比。
2. **天气单位切换**：温度 °C／°F，风速 km/h／m/s／mph；数据层继续保存标准单位，仅在显示时转换。
3. **自定义 NTP 服务器**：用户服务器优先，内置服务器兜底；保留现有 IANA 时区和自动夏令时。
4. **多主题自动轮播**：从已安装主题中勾选多个，按间隔切换，切换时不反复写 Flash。
5. **经典主题预设**：提供经典 24 小时、12 小时 AM/PM、像素动画时钟等 `.stheme`，把参考设备的时间格式、颜色和字体能力转化为可直接安装的主题，而不是重复增加一批全局设置。

### 1.3 暂缓与不做

- **原生 JPG／GIF 相册暂缓**：NM-TV-154 的文件系统只有 192 KiB，且全功能固件余量有限。优先采用“电脑端转换 → `.stheme` → 设备渲染”的路线。
- **天气 API Key 设置不照搬**：当前天气数据代码使用 wttr.in，地点搜索使用 Open-Meteo Geocoding，不需要 OpenWeather Key。
- **手动 UTC 偏移不照搬**：当前 IANA 时区和自动 DST 更可靠。
- **独立多页面导航不照搬**：当前单页标签、统一保存和中文界面更完整。
- **气压与多日预报不进首发**：需要扩展数据结构和屏幕布局，价值与资源占用需单独评审。

### 1.4 首发前必须修正的现存问题

这两项不是参考设备的新功能，但会直接影响天气产品体验：

1. `WeatherMode.cpp` 当前把标题固定写成 `Seoul Weather`，更换坐标后仍会显示 Seoul。
2. `webui.html` 写的是 Open-Meteo 提供天气数据，而 `WeatherClient.cpp` 实际通过 wttr.in 获取天气；Open-Meteo 当前用于地点搜索。应统一文案或统一实现，避免误导用户。

## 2. 参考设备网页功能清单

## 2.1 Network：网络配置

页面：`/network.html`

| 功能 | 产品表现 |
| --- | --- |
| Wi-Fi 扫描 | 下拉列表展示附近 SSID，并显示信号百分比及 Strong／Medium／Weak 分级 |
| 重新扫描 | `RESCAN` 主动刷新列表 |

## 3. NM-TV-154 当前基线与硬约束

## 3.1 已具备的产品基础

当前项目已经具备：

- 最多 4 个 Wi-Fi，启动时优先连接可见的最强网络，断线后可切换。
- Wi-Fi 扫描、RSSI dBm、2.4 GHz 提示、mDNS 主机名和配置热点。
- 天气刷新间隔、经纬度、城市搜索和韩国城市快捷预设。
- Timer 四时段调度和 Carousel 应用轮播。
- 可安装、选择、删除的 `.stheme` 主题；主题可参与应用 Carousel。
- 主题文本、图片、动画、形状、自定义字体、时间和日期 token。
- 日间亮度、定时夜间亮度、日出日落亮度和面板色彩校正。
- 手动 OTA、GitHub 更新、配置备份、密码保护、重启和恢复出厂。
- 股票、用量、雷达、Home Assistant、通知、烧屏防护和 WireGuard 等差异化功能。

因此，本需求应定义为**体验补强**，不是“把 Ultra 功能全部移植过来”。

## 3.2 Flash 与文件系统

| 项目 | 当前值 | 产品含义 |
| --- | --- | --- |
| Flash | 4 MB | 不适合无约束增加解码器和素材 |
| OTA 单槽 | 1,966,080 B | 新代码必须同时通过两个 NM-TV-154 构建的大小检查 |
| 当前 `smalltv_esp32_wg` | 1,895,120 B | 本地实测与构建文档一致 |
| 当前 OTA 余量 | 70,960 B（3.6%） | 原生 JPG／GIF 解码器风险高 |
| LittleFS | 192 KiB | 配置、主题、OTA 状态和用户素材共享 |
| 韩文字库 | NM-TV-154 不内置 | 设备屏仅保留 Galmuri ASCII；新增文本需避免 unsupported UTF-8 显示为 `?` |

**发布原则：**本轮不调整分区、不删除 WireGuard／雷达／HA 来换空间，不承诺固定相册张数，以实际包大小和剩余空间为准。

## 5. 推荐需求明细

## 5.1 P0：天气正确性修正

### 产品要求

1. 天气页标题不再固定为 Seoul。
2. 地点搜索或快捷预设选中后，Web UI 显示完整地点名称。
3. NM-TV-154 屏幕标题使用 ASCII 安全名称；无法安全显示时使用通用 `Weather`，不能出现 `?`。
4. 页面准确区分：
   - 地点搜索：Open-Meteo Geocoding；
   - 天气数据：以实际 `WeatherClient.cpp` 实现为准。
5. 保存和升级后，地点及天气设置保持。

### 建议落点

- `src/features/weather/WeatherMode.cpp`
- `src/features/weather/WeatherClient.cpp`（仅在决定统一数据源时修改）
- `src/Settings.h`、`src/Settings.cpp`（如保存地点名称）
- `src/webui.html`

### 验收

- 选择 Busan、北京或自定义坐标后，不再显示 `Seoul Weather`。
- 非 ASCII 地名在 NM-TV-154 上不产生乱码。
- Web UI 的数据源说明与实际请求一致。

## 5.2 P1：Wi-Fi 信号分级

### 产品要求

- 扫描结果继续按 RSSI 从高到低排序。
- 每项显示 SSID、加密状态、强／中／弱和原始 dBm。
- 建议初始阈值：Strong ≥ -60 dBm，Medium 为 -75～-61 dBm，Weak < -75 dBm；阈值在代码中集中定义。
- 不强制显示百分比；如产品坚持百分比，必须同时保留 dBm，并注明为估算值。

### 建议落点

仅修改 `src/webui.html` 的扫描结果渲染，无需修改设置结构或网络连接逻辑。

### 验收

- 扫描、选择、填充密码的原流程不变。
- SSID 仍经过 HTML 转义。
- 强中弱边界和空列表表现正确，中英文界面均有文案。

## 5.3 P1：天气单位切换

### 产品要求

- 温度：°C／°F。
- 风速：km/h／m/s／mph。
- Web UI 可显示 ° 符号；NM-TV-154 设备屏默认用 `C`／`F`，避免 ASCII 字库缺字。
- `WeatherData` 继续以 C、km/h 保存，不在网络客户端中混存单位。
- 默认保持现有 C、km/h，旧配置升级无感。

### 建议落点

- `src/Settings.h`、`src/Settings.cpp`：增加天气单位字段及默认值、校验、JSON 往返。
- `src/webui.html`：Weather 页增加单位控件和中英文文案。
- `src/features/weather/WeatherMode.cpp`：渲染时转换和格式化。
- `WeatherClient.cpp` 无需因单位切换修改。

### 验收

- 0°C 显示为 32°F；100 km/h 正确转换为约 62.1 mph、27.8 m/s。
- 当前温度、最高／最低温度使用同一单位。
- 保存、重启、导出／导入后单位保持。
- 240×240 屏幕无文字溢出，NM-TV-154 无 `?` 字符。

## 5.4 P1：自定义 NTP 服务器

### 产品要求

- 增加可选 `NTP Server` 输入项，留空使用当前内置服务器。
- 填写后作为首选，`pool.ntp.org`／`time.nist.gov` 继续兜底。
- 自定义服务器或时区变化时重新 arm SNTP；普通保存不做无意义重连。
- 保留夜间模式的 NTP 可信窗口和 WireGuard 对时间的要求。
- 不提供手动 UTC Offset 替代项。

### 建议落点

- `ClockSettings` 及 `Settings.cpp`
- `src/Clock.cpp`：记录已生效的 NTP 配置，和时区一样参与 reapply 判断。
- `src/Platform.h`：复用现有双服务器入口。
- `src/webui.html`：Clock & night mode 卡片增加输入项。

### 验收

- 留空时行为与当前版本一致。
- 自定义地址不可用时能回退，不导致夜间模式或 WireGuard 永久卡死。
- 修改服务器后无需恢复出厂；旧配置导入时自动使用默认值。

## 5.5 P1：多主题自动轮播

### 产品要求

- Display → Theme clocks 增加：启用轮播、切换间隔、已安装主题多选。
- 仅列出有效主题；失效或已删除主题自动跳过，并保留可见错误信息。
- 当前选中的 `themeId` 作为默认／首个主题，轮播时只改运行态，不在每次切换时保存配置。
- 主题模式可独立轮播；参与应用 Carousel 时，主题内部轮播不得破坏应用 dwell 和触摸暂停逻辑。
- 通知结束后恢复通知前的运行主题，不额外写入 Flash。
- 首版建议最多勾选 4 个主题，实际可安装数量仍受 LittleFS 剩余空间限制。

### 建议落点

- `src/Settings.h`、`src/Settings.cpp`：轮播开关、间隔和主题 ID 列表。
- `src/features/theme/ThemeMode.h/.cpp`：区分配置默认 ID 与运行态 active ID，管理轮换时钟和加载状态。
- `src/main.cpp`：明确与应用 Carousel、手动预览和暂停的交互。
- `src/webui.html`：基于 `/api/themes` 生成多选列表。
- 不新增图片解码器。

### 验收

- 2～4 个主题按间隔循环，重启后从默认主题开始。
- 连续运行 24 小时无持续堆内存下降，无配置 Flash 高频写入。
- 删除轮播中的主题、包损坏、空间不足、通知覆盖、触摸暂停均有确定行为。
- 单主题和未启用轮播时与当前版本一致。

## 5.6 P1：经典主题预设

### 建议首批主题

| 主题 | 覆盖的参考能力 | 实现方式 |
| --- | --- | --- |
| Classic 24 | 大字体 24 小时、日期、时分独立颜色 | 纯 `.stheme` |
| Classic 12 | 12 小时、AM/PM、短日期 | 纯 `.stheme` |
| Pixel Motion | 动画背景／角色、时间、日期 | 图片帧＋`.stheme` |

### 产品价值

- 用户不用先理解主题格式，即可获得接近 Ultra 的“开箱即有多个表盘”体验。
- 颜色、字体、日期格式由主题承载，避免设置页继续膨胀。
- 不需要新增固件解码器；主题包仍需通过 NM-TV-154 实际存储检查。

### 注意

实时天气主题需要可绑定的数据。现有固件的 `device.*` 天气 token 文档明确标为未提供，不能用静态示例冒充实时天气。实时天气主题应另行设计数据源或内置天气绑定。

## 6. P2 候选功能

## 6.1 开机延迟连接 Wi-Fi

**建议行为：**

- 设置范围建议 0–120 秒，默认 0。
- 只影响开机后的首次 STA 连接，不影响运行中断线重连。
- 显示倒计时，允许触摸跳过。
- 不使用长时间 `delay()` 阻塞显示、触摸和系统状态处理。
- 无已保存网络时直接进入 AP，不做无意义等待。

**优先级理由：**对路由器启动慢的用户有价值，但适用面小于单位、NTP 和主题轮播。

## 6.2 冒号闪烁

优先在主题引擎增加轻量 token 或可见性绑定能力，例如偶数秒显示、奇数秒隐藏；不要为单一效果新建整套全局时钟设置。该功能价值较低，应在主题轮播之后实现。

## 6.3 气压与多日预报

- 气压需扩展 `WeatherData`、数据源过滤字段、单位换算和 WeatherMode 布局。
- 多日预报需新增数据集合、刷新策略、页面或主题绑定。
- 建议先完成天气单位与地点正确性，再以独立需求评审，不在首发顺带加入。

## 7. 相册与 GIF 的推荐产品方案

## 7.1 不建议的方案

不在 NM-TV-154 全功能固件中直接复制以下方案：

- 额外占用固件空间的软件 JPEG 解码器（2026-11-20 修订：经典 ESP32 采用 ROM 自带的 baseline JPEG 解码，通过 4 KiB 工作区逐块输出，支持全彩照片）；
- 设备端 GIF 解码器；
- 无配额的大量图片上传；
- 为相册重新调整分区并强迫用户 USB 迁移；
- 以牺牲 WireGuard、OTA 安全余量或配置空间换取素材容量。

参考设备本次页面中已出现一个约 266 KB 的 GIF，而 NM-TV-154 整个 LittleFS 只有 192 KiB，单个文件就已经无法容纳。

## 7.2 推荐的替代路线：Album Theme

### 用户流程

1. 用户在电脑端选择 JPG／GIF。
2. 工具统一缩放到 240×240，并转换为现有 STI 图片／帧格式。
3. 工具生成相册 `.stheme`。
4. 用户通过现有 Display → Theme clocks 安装、选择和删除。
5. 设备复用 ThemeMode 渲染，不在运行时解码 JPG／GIF。

### 需要的补强

- 静态单图：现有主题图片层已经可承载。
- 多图轮播：给动画帧增加**每帧停留时间**或相册 dwell，避免用重复帧模拟 5 秒停留。
- 工具侧：尺寸、帧数、总包大小和目标设备检查。
- 设备侧：沿用现有 freeBytes、上传暂存、完整校验和原子 rename。
- 配额：为配置和至少一个时钟主题保留空间，不承诺固定图片张数。

### 定位

- NM-TV-154：轻量相册主题，适合少量优化后的图片或短动画。
- 8 MB SmallTV Pro：后续可评估更完整的相册管理，但仍优先复用预处理格式。

## 10. 测试与发布门槛

## 10.1 构建

每次涉及共享代码的变更都要构建：

```bash
pio run -e smalltv_esp32
pio run -e smalltv_esp32_wg
python tools/ci_checks.py size --min-free 8192 --allow-missing
```

当前本地基线：

```text
smalltv_esp32_wg  1895120 / 1966080 B
free              70960 B (3.6%)
status            ok
```

新功能不能只验证无 WireGuard 版本；`smalltv_esp32_wg` 是最紧的发布约束。

## 10.2 功能回归

- Wi-Fi：扫描、隐藏 SSID、多网络切换、错误密码、AP 回退、mDNS。
- 天气：单位边界、负数温度、地点搜索、请求失败退避、刷新间隔。
- 时间：空 NTP、错误 NTP、回退、DST、跨午夜夜间模式、WireGuard 校时。
- 主题：无主题、单主题、多主题、损坏包、删除当前包、空间不足、上传中断。
- 轮播：应用 Carousel、Timer、触摸预览／暂停、通知覆盖与恢复。
- 配置：旧版本升级、导出／导入、恢复出厂、重启后保持。
- 显示：240×240 布局、ASCII 字库、通知叠加、夜间亮度。
- 资源：连续轮播的 free heap／largest block、Flash 写入次数和 OTA 大小。

## 10.3 发布说明必须写明

- 新增设置项的默认值和升级兼容性。
- NM-TV-154 的相册容量按实际包大小计算。
- 不修改分区；若未来改变分区，必须单独提供 factory 固件和 USB 迁移说明。
- 主题文件不包含在设置导出中，用户仍需保存自己的 `.stheme` 文件。
