# SmallTV NM 3.13.0 检索与命名更新复盘

2026-11-21

## 产品决策

采用 SmallTV NM 作为界面名称、smalltv-nm 作为固件标识，版本升级到 3.13.0。已有网络地址和集成配置保留。城市、时区、股票、交易对采用“本地常用数据 + 按输入在线检索 + 手动配置”的方式，查询和选择不写入设备配置。

Open-Meteo 城市接口实测支持 CORS；Binance 公共数据域支持 CORS，查询参数过滤为活跃 Spot 并关闭 permissionSets，将首次目录响应从约 18 MB 缩减到约 2.6 MB，精简后才缓存。Yahoo 搜索接口实测未提供 CORS，因此由设备提供固定主机查询入口。Naver 自动补全实测被拒绝，不承诺任意名称在线查询。

## 流程与边界

1. 城市结果显示名称、行政区、国家、坐标和时区，需要明确选中。Weather／Display 同步设备位置，独立雷达不修改它。
2. 时区本地检索保留当前选项及自定义 POSIX 规则；不支持的城市时区不会降级为 UTC，提供提示。
3. 股票结果带来源和市场，填入草稿空行并去重，不把不同来源的符号当成同一标的。精确中文别名可转换为代码；ON、CAT 等短代码不会被部分名称匹配替换。
4. 活跃 Spot 目录用于成功的联网结果；目录不可用时标记离线预设。浏览器缓存、输入法、过期请求和网络失败不应改变已保存配置。
5. 股票查询沿用鉴权，固定 Yahoo 主机，不接受调用者 URL。限制输入、读取字节数、结果数、调用频率以及 TLS 握手时间。旧型号支持离线常用库和手工配置。

## 容量与回归

保留当前分区和全部功能，生成网页打包并压缩；天气字形用每个字形独立的轻量 LZ 编码，数字缓冲 800 字节、标签缓冲 240 字节。105 个字形已用真实 C++ 解码器输出，与原始字体采样逐字节比较。

新增 Node 测试覆盖别名、缓存失败与过期、IME／防抖、旧请求隔离、无自动选中、雷达独立性、自定义时区保留、股票来源与去重、不保存检索结果；同时测试实际 gzip 中的生成脚本。新增 native 测试覆盖查询校验、URL 编码、输入流上限及 Yahoo JSON 规范化。独立审查发现并修复短代码查询替换和默认 TLS 120 秒握手的问题。

中英文手册第二版各 17 页、14 章，已渲染检查。全部 22 个 Node 测试文件通过，受影响的模式、天气与检索 native 测试通过，实际压缩网页脚本测试通过。

最终标准版为 1,910,976 字节，OTA 余量 55,104 字节；WireGuard 版为 1,956,512 字节，OTA 余量 9,568 字节。双版本构建及至少保留 8,192 字节的容量检查均通过。

## 实机升级与检索验证

已将发布包中校验通过的 WireGuard OTA 更新至 192.168.124.14。设备回报 `smalltv-nm 3.13.0 (esp32-wg)`，网页内容与发布包逐字节一致。升级前后 `/api/config` 全部字段一致，10 个内置全彩 v2 图片包有效，文件系统剩余 32,768 字节。本次图片库内容未变，无需重新上传。

COM3（115200）捕获到 `[boot] done`；升级后的 63 秒专项观察内 uptime 持续增加，未发现 assert、Guru Meditation 或 Backtrace。观察结束时空闲堆为 178,400 字节，最大空闲块为 69,620 字节。浏览器后续检查时 uptime 已约 5 分钟，未见重启。该记录证明本轮短期运行情况，不代表长期稳定性试验或实体屏幕视觉验收。

设备股票查询 `AAPL` 和 `ON` 均 HTTP 200，分别用时 2.19 秒和 2.88 秒，结果包含对应代码。浏览器已验证：上海中文查询及明确选择、Weather／Display 坐标同步、纽约时区别名过滤且保留当前时区、微软检索返回 MSFT 及相关标的、选择后新增 Yahoo 草稿行、比特币查询返回多个活跃 Binance Spot 交易对。检索后均未保存，最后刷新清除测试草稿。

设备验证摘要附于发布包 `device-verification.json`。公开查询接口仍受网络及服务商策略影响；Naver 更多股票以常用列表和手工代码为入口，城市时区以设备已支持的规则为准。
